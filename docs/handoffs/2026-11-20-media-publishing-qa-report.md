## 二、 測試過程中發現的異常與待優化項目（QA Findings）

### 1. 發布失敗後草稿／貼文從列表消失（如 Action 71）

- **現象**：當執行發布發生錯誤（Action 狀態轉為 `FAILED`）後，該筆貼文在前端工作區的當前列表中直接消失，無法直接在原卡片上檢視失敗原因或點擊「建立新版本」進行重試。
- **原因推測**：前端篩選邏輯可能僅顯示特定進行中狀態（如 `DRAFT`、`PENDING_REVIEW`、`SCHEDULED`、`SUCCEEDED`），未將 `FAILED` 狀態納入「需處理／歷史版本」顯示範圍。
- **建議修復**：在前端列表保留 `FAILED` 狀態卡片並顯示錯誤訊息（如 `error_message`），同時提供一鍵「基於此失敗版本建立新版本 (Retry as New Version)」按鈕。

### 2. 兩張圖片輪播文案中的「報名連結」無法刪除或修改

- **現象**：編輯兩張圖片輪播草稿的文案（Caption）時，若將內文中的報名連結刪除，系統會自動將該連結補回，導致無法移除或替換。
- **原因推測**：後端 `content_drafts.py` 或前端表單在序列化／儲存文案時，可能設有「強制附加／自動補齊活動報名連結（Registration URL）」的防呆邏輯，只要偵測不到原連結字串就會自動拼接回文末。
- **建議修復**：將報名連結改為獨立欄位或允許使用者手動覆寫／關閉自動附加，避免強制回填覆蓋人工編輯結果。

### 3. Cloudflare R2 未設定時貼上外部連結仍提示「缺少影音素材需求」

- **現象**：因本機尚未設定 Cloudflare R2 環境變數，改以手動貼上公開 HTTPS 媒體網址的方式測試；然而在貼上連結後，介面仍提示「送交人工審核前需要完成：影音素材需求」。
- **原因推測**：前端或後端的送審前置檢查（Pre-review validation）可能過度依賴 `media_assets` 資料表（R2 上傳紀錄）或特定的 `media_items` 結構欄位，未將「手動輸入的外部公開 URL」同步計入已滿足素材條件的判斷中。
- **建議修復**：統一素材驗證口徑——只要 `meta_adapter_payload` 或媒體清單中已具備合法且符合該貼文形式數量要求的公開 HTTPS URL（無論來自 R2 上傳或手動貼上），即判定滿足「影音素材需求」並解除送審阻擋。
