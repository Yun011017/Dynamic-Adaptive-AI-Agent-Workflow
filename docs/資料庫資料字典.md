# 資料庫資料字典

## 共通規則

- 除了 `workspaces` 以外，每張業務資料表都有 `id`、`workspace_id`、`created_at` 三個共通欄位。
- `workspace_id` 是租戶隔離鍵；查詢、更新或建立關聯資料時都必須帶同一個 workspace，不能只用 `id` 跨工作區存取。
- `created_at` 由資料庫以時區時間自動寫入。現有資料表沒有通用的 `updated_at` 欄位。
- 多數跨表關聯使用 `(workspace_id, id)` 複合外鍵，確保同一筆 Strategy、執行紀錄、草稿不會跨 workspace 串接。
- `JSON` 欄位保存變動較快的輸入、輸出與平台 payload；需要以欄位搜尋、排序或加限制的資料，才會提升成實體欄位。

## 資料關係總覽

```text
workspaces
 ├─ members
 ├─ goals
 │   ├─ strategies ── executions ── execution_actions ── approval_requests
 │   │                    │
 │   │                    └─ observations
 │   └─ agent_runs ── agent_run_checkpoints
 └─ external_events ── form_responses
                      └─ observations
```

---

## 1. `workspaces`（工作區）

系統的最高資料隔離單位，例如 development 工作區。其他業務資料都會歸屬於一個工作區。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵，工作區識別碼。 |
| `slug` | `VARCHAR(100)` | 是 | 人類可讀、全系統唯一的工作區代號，例如 `development`。用於設定與 API 選取工作區。 |
| `name` | `VARCHAR(255)` | 是 | 工作區顯示名稱。 |
| `status` | `VARCHAR(32)` | 是 | 工作區狀態，預設 `active`。目前模型未額外限制可用值。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間，由資料庫自動填入。 |

限制：`slug` 唯一。

---

## 2. `members`（工作區成員／服務身分）

保存可在工作區內操作的人或 Agent 身分，提供基礎角色控管。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區，外鍵至 `workspaces.id`。 |
| `subject_id` | `VARCHAR(255)` | 是 | 外部身分系統或服務帳號的識別字串。 |
| `role` | `VARCHAR(16)` | 是 | 角色，目前只允許 `Admin` 或 `Agent`。 |
| `status` | `VARCHAR(32)` | 是 | 成員狀態，預設 `active`。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

限制：同一工作區中 `subject_id` 唯一；`role` 僅可為 `Admin`、`Agent`。

---

## 3. `goals`（目標）

行銷或營運目標的主資料。一個 Goal 可以有多個版本的 Strategy，也可對應多次 Agent 執行。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `title` | `VARCHAR(255)` | 是 | 目標標題，例如提升某工作坊報名人數。 |
| `description` | `TEXT` | 否 | 補充目標背景與說明。 |
| `status` | `VARCHAR(32)` | 是 | 目標狀態，預設 `active`。 |
| `kpi_definition` | `JSON` | 是 | KPI 定義，例如目標數值、衡量方式、期間。預設 `{}`。 |
| `constraints` | `JSON` | 是 | 執行限制，例如活動期間、受眾、渠道限制。預設 `{}`。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

關聯：`strategies.goal_id`、`agent_runs.goal_id` 會指向此表，且必須在相同 workspace。

---

## 4. `strategies`（策略版本）

Agent 或人工整理出來的策略內容。一個 Goal 可保留多個版本，版本號由 `version` 區分。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `goal_id` | `BIGINT` | 是 | 所屬目標，複合外鍵至同 workspace 的 `goals`。 |
| `version` | `INTEGER` | 是 | 該 Goal 下的策略版本，從 1 開始。 |
| `content` | `TEXT` | 是 | 完整策略正文，供畫面呈現、建立內容提案與後續執行使用。 |
| `rationale` | `TEXT` | 否 | 產生此策略的理由、資料依據或補充說明。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

限制：同一 `(workspace_id, goal_id, version)` 唯一，且 `version > 0`。

---

## 5. `executions`（策略執行紀錄）

紀錄某一版 Strategy 的工作流程執行結果。內容草稿屬於某次執行下的 `execution_actions`。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `strategy_id` | `BIGINT` | 是 | 使用的 Strategy，複合外鍵至同 workspace 的 `strategies`。 |
| `status` | `VARCHAR(32)` | 是 | 工作流程狀態，預設 `QUEUED`。 |
| `result_summary` | `TEXT` | 否 | 執行結果的摘要，供工作詳情區塊呈現。 |
| `evaluation_result` | `JSON` | 否 | 最新 KPI 評估快照，例如計算結果、指標比較與結論。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

`status` 允許值：`QUEUED`、`RUNNING`、`WAITING_APPROVAL`、`WAITING_OBSERVATION`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`MANUAL_REVIEW`。

---

## 6. `execution_actions`（執行動作／內容草稿版本）

通用的工具動作表；目前 Instagram 內容提案、版本歷史、排程與發布動作都保存於這張表。內容本體和媒體資料位於 `payload` JSON。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵；審核請求的 `action_id` 會指向此欄位。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `execution_id` | `BIGINT` | 是 | 所屬策略執行紀錄，複合外鍵至 `executions`。 |
| `tool` | `VARCHAR(64)` | 是 | 要呼叫的工具／平台名稱，例如 Meta adapter。 |
| `operation` | `VARCHAR(64)` | 是 | 動作名稱，例如建立草稿、發布貼文。 |
| `status` | `VARCHAR(32)` | 是 | 草稿、審核、排程與實際執行狀態，預設 `DRAFT`。 |
| `draft_version` | `INTEGER` | 是 | 同一內容動作的草稿版本，從 1 開始。 |
| `content_hash` | `VARCHAR(64)` | 是 | 本版內容雜湊，用來確認審核的是哪一份內容並偵測變更。 |
| `payload` | `JSON` | 是 | 平台動作的詳細資料，例如 caption、圖片／影片網址、排程時間與 Meta adapter payload。預設 `{}`。 |
| `idempotency_key` | `VARCHAR(255)` | 是 | 冪等鍵；同一 workspace 不可重複，避免重送後重複建立或發布。 |
| `external_id` | `VARCHAR(255)` | 否 | 外部平台回傳的貼文／草稿識別碼。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

`status` 允許值：`DRAFT`、`SCHEDULED`、`PENDING_REVIEW`、`APPROVED`、`REJECTED`、`EXPIRED`、`EXECUTING`、`SUCCEEDED`、`FAILED`、`TIMEOUT`、`VERIFYING`、`MANUAL_REVIEW`、`SUPERSEDED`。

限制：`draft_version > 0`；同一 `(workspace_id, idempotency_key)` 唯一。

### `execution_actions.payload`：Instagram 內容提案常用鍵

以下不是獨立資料庫欄位，而是目前內容提案流程寫入 `payload` 的 JSON 結構；其他工具的 action 可使用不同結構。

| JSON 鍵 | 用途 |
| --- | --- |
| `strategy_id`、`strategy_version` | 建立內容提案時使用的策略識別與版本資訊。 |
| `channel` | 發布渠道，目前為 `instagram`。 |
| `post_format` | 貼文形式：`image`（圖片貼文）、`mixed_carousel`（多媒體貼文）、`reel`（短影片）。 |
| `carousel` | 當 `post_format = image` 時，區分單張圖片與多張圖片。 |
| `title` | 內容提案名稱。 |
| `caption` | Instagram 文案本文。 |
| `hashtags` | hashtag 陣列；送給 adapter 前會組合至 caption。 |
| `image_requirements` | 圖片素材需求清單，每行一項。 |
| `video_requirements` | 影音素材需求清單，每行一項。 |
| `image_urls` | 公開 HTTPS 圖片網址陣列。 |
| `video_urls` | 公開 HTTPS 影片網址陣列。 |
| `scheduled_at` | 預計發布時間（ISO 8601 時區時間）。 |
| `schedule_requested` | 是否已設定排程意圖。 |
| `proposal_version` | 前端顯示用內容提案版本。 |
| `meta_adapter_payload` | 轉換後交給 Meta 發布 adapter 的資料。 |

目前送交人工審核前的業務驗證：必須填寫未來的 `scheduled_at`，以及至少兩個公開 HTTPS 媒體網址；圖片貼文需圖片、Reel 需影片、多媒體貼文則圖片與影片都至少一個。

## 7. `approval_requests`（人工審核請求）

保存每次送交人工審核時的快照與決策。審核的是某個 action 的特定內容版本，不能只依 action 的最新內容判斷。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `action_id` | `BIGINT` | 是 | 被審核的 `execution_actions.id`，複合外鍵至同 workspace 的 action。 |
| `draft_version` | `INTEGER` | 是 | 送審當下的草稿版本。 |
| `content_hash` | `VARCHAR(64)` | 是 | 送審當下的內容雜湊，確保審核結果可對應正確內容。 |
| `status` | `VARCHAR(32)` | 是 | 審核狀態，預設 `PENDING_REVIEW`。 |
| `decision_reason` | `TEXT` | 否 | 退回或拒絕原因、審核備註。 |
| `requested_by` | `VARCHAR(255)` | 是 | 送審者，預設 `admin`。 |
| `reviewed_by` | `VARCHAR(255)` | 否 | 做出決策的審核者。 |
| `requested_at` | `TIMESTAMPTZ` | 是 | 送審時間。 |
| `decided_at` | `TIMESTAMPTZ` | 否 | 核准、拒絕或到期的決策時間。 |
| `expires_at` | `TIMESTAMPTZ` | 否 | 審核逾期時間；若未設定則不自動逾期。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

`status` 允許值：`PENDING_REVIEW`、`APPROVED`、`REJECTED`、`EXPIRED`。`action_id` 已建立索引，供待審佇列與審核詳情查詢。

---

## 8. `agent_runs`（Agent 執行紀錄）

保存 FastAPI 啟動 Agent／LangGraph 工作時的輸入、輸出、重試與失敗狀態。它與 `executions` 分工不同：前者追蹤 Agent 運算過程，後者追蹤 Strategy 後續工作流程。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 內部主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `run_id` | `VARCHAR(36)` | 是 | 對外／流程使用的唯一執行 ID。 |
| `goal_id` | `BIGINT` | 否 | 對應的 Goal；舊資料可能為空，新 API 建立的 run 應有值。 |
| `status` | `VARCHAR(16)` | 是 | Agent 執行狀態，預設 `PENDING`。 |
| `input_payload` | `JSON` | 是 | 啟動 Agent 時使用的輸入與上下文。預設 `{}`。 |
| `output_payload` | `JSON` | 否 | Agent 完成後輸出，例如產生的 Strategy 結果。 |
| `error_code` | `VARCHAR(64)` | 否 | 可程式判讀的失敗代碼。 |
| `error_message` | `TEXT` | 否 | 失敗詳細訊息。 |
| `agent_provider` | `VARCHAR(32)` | 是 | 使用的模型供應商，預設 `local`。 |
| `agent_model` | `VARCHAR(128)` | 是 | 實際模型名稱，預設 `deterministic-langgraph`。 |
| `attempts` | `INTEGER` | 是 | 已執行／重試次數，預設 `0`。 |
| `next_retry_at` | `TIMESTAMPTZ` | 否 | 可再次重試的時間。 |
| `started_at` | `TIMESTAMPTZ` | 否 | 實際開始執行時間。 |
| `finished_at` | `TIMESTAMPTZ` | 否 | 結束時間。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

`status` 允許值：`PENDING`、`RUNNING`、`COMPLETED`、`FAILED`。`run_id` 全系統唯一，`goal_id` 與 `run_id` 都有查詢索引。

---

## 9. `agent_run_checkpoints`（Agent 執行檢查點）

保存 Agent 長流程各階段的可恢復狀態，讓 worker 重試時不必從頭運算。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `agent_run_id` | `BIGINT` | 是 | 所屬 Agent run，複合外鍵至 `agent_runs`。 |
| `sequence` | `INTEGER` | 是 | 此 run 的檢查點流水號，從 1 開始。 |
| `phase` | `VARCHAR(32)` | 是 | 流程階段名稱，例如資料讀取、策略產生、寫入結果。 |
| `state_payload` | `JSON` | 是 | 該階段需要保存的狀態資料。預設 `{}`。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 建立時間。 |

限制：`sequence > 0`；同一 `(workspace_id, agent_run_id, sequence)` 唯一。

---

## 10. `external_events`（外部事件原始資料）

外部來源匯入的原始事件，例如表單提交、社群平台回呼或其他資料來源。先保存未加工資料，再由後續流程轉成結構化資料。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `provider` | `VARCHAR(64)` | 是 | 資料來源／供應商名稱。 |
| `source_account` | `VARCHAR(255)` | 是 | 來源帳號或資料集識別。 |
| `source_object_id` | `VARCHAR(255)` | 是 | 來源端物件 ID，例如表單回覆 ID。 |
| `source_version` | `VARCHAR(255)` | 是 | 來源物件版本或修訂號。 |
| `event_type` | `VARCHAR(64)` | 是 | 事件種類，例如表單提交。 |
| `raw_payload` | `JSON` | 是 | 原始事件完整內容，保留以供重新正規化或除錯。 |
| `processing_status` | `VARCHAR(32)` | 是 | 匯入／處理狀態，預設 `RECEIVED`。 |
| `attempts` | `INTEGER` | 是 | 處理或重試次數，預設 `0`。 |
| `next_retry_at` | `TIMESTAMPTZ` | 否 | 下次可重試時間。 |
| `error_code` | `VARCHAR(64)` | 否 | 最後一次處理失敗代碼。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 接收並寫入時間。 |

限制：`attempts >= 0`；同一 `(workspace_id, provider, source_account, source_object_id, source_version)` 唯一，避免重複匯入同版本事件。

---

## 11. `form_responses`（結構化表單回覆）

從 `external_events` 正規化出來的表單欄位，供 Agent 分析受眾、參與意願與活動需求。原始資料仍保留在 `external_events.raw_payload`。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `external_event_id` | `BIGINT` | 是 | 對應的原始外部事件，複合外鍵至 `external_events`。 |
| `source_id` | `VARCHAR(255)` | 是 | 原始來源中的回覆或提交識別碼。 |
| `is_member` | `BOOLEAN` | 否 | 受訪者是否為社團成員；未知時為 `NULL`。 |
| `will_attend` | `BOOLEAN` | 否 | 受訪者是否表示願意參加；未知時為 `NULL`。 |
| `school` | `VARCHAR(255)` | 否 | 學校。 |
| `department_grade` | `VARCHAR(255)` | 否 | 系級或年級資料。 |
| `activity_name` | `VARCHAR(255)` | 否 | 感興趣或填寫的活動名稱；現行流程主要使用此欄位。 |
| `event_date` | `DATE` | 否 | 舊版活動日期欄位，僅保留相容歷史資料；現行流程不再寫入或讀取。 |
| `submitted_at` | `TIMESTAMPTZ` | 否 | 使用者原始提交時間。 |
| `normalization_errors` | `JSON` | 是 | 欄位轉換失敗或無法辨識的資訊，預設 `[]`。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 正規化資料建立時間。 |

限制：同一 `(workspace_id, external_event_id)` 只允許一筆結構化回覆。

---

## 12. `observations`（成效觀測值）

保存從外部事件取得的量化成效，能選擇性歸因至某個 Strategy 或 Execution，供 KPI 評估使用。

| 欄位 | 型別 | 必填 | 意義與用途 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 主鍵。 |
| `workspace_id` | `BIGINT` | 是 | 所屬工作區。 |
| `external_event_id` | `BIGINT` | 是 | 觀測值來源事件，複合外鍵至 `external_events`。 |
| `strategy_id` | `BIGINT` | 否 | 可選的歸因 Strategy，複合外鍵至 `strategies`。 |
| `execution_id` | `BIGINT` | 否 | 可選的歸因 Execution，複合外鍵至 `executions`。 |
| `metric` | `VARCHAR(100)` | 是 | 指標名稱，例如報名數、點擊數、觸及數。 |
| `value` | `NUMERIC(20,6)` | 是 | 指標數值，保留小數精度。 |
| `observed_at` | `TIMESTAMPTZ` | 是 | 此數值實際被觀測到的時間。 |
| `attribution_status` | `VARCHAR(32)` | 是 | 歸因狀態，預設 `unattributed`。 |
| `created_at` | `TIMESTAMPTZ` | 是 | 寫入時間。 |

限制：同一 `(workspace_id, external_event_id, metric, observed_at)` 唯一，避免同一來源在同一時點重複寫入同一指標。

## 資料維護注意事項

1. migration 採 forward-only 設計；正式環境若需回退，應由已驗證備份還原，而不是直接執行 downgrade。
2. 不要直接以 `id` 連表或修改資料；所有跨表操作都應同時帶上 `workspace_id`。
